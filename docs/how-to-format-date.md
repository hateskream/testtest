# How to Format Date

Данный файл описывает **как форматировать дату и время с учетом локали** в проекте.

- ✅ `getDateFormatter()` - основной и рекомендуемый способ форматирования дат в проекте
- ❌ `toLocaleDateString()` - допустим только для редких и нерекурсивных вызовов

---

## toLocaleDateString()

Стандартный метод Date позволяет это делать без ручного объявления Intl.

**Особенности:**

- на **каждый вызов** происходит создание нового форматтера без гарантий кеширования (спецификация не обязывает движок кешировать `Intl.DateTimeFormat`)
- требует указания локали (undefined для текущей пользовательской)
- ничего не кеширует. Согласно спецификации он не должен этого делать

Вызов этого метода для большого списка объектов внутри `computed + map` - это перерасчет таблиц каждый раз

**Юзкейсы:**

- форматирование небольшого количества данных, которое еще и редко будет меняться. Например, компонент принимает props date.
- форматирование единичных значений (например, заголовок, tooltip, статический текст)

---

## getDateFormatter()

Генерация и кеширование `Intl.DateTimeFormat` по комбинации `options` + `locale`.

Это значит, что `weekdayFormatter`, который часто используется в разных модулях, будет сформирован один раз и эффективнее обработает большое количество данных.

**Особенности:**

- принимает объект `options`, который соответствует опциям из `Intl`/`toLocaleDateString`.
- можно указать конкретную локаль при необходимости (`getDateFormatter({ locale: 'ru', ... })`)
- без указания локали сам выбирает локаль, основываясь на конфигурации проекта (`VITE_FEATURE_DATE_FORMAT_LOCALIZATION`)
	- если фича-флаг отключен, то будет применена локаль `en-US` (локаль, по которой преимущественно проектируется наш интерфейс)
  - если фича-флаг включен, то будет применена локаль пользователя
- возвращает объект с методом `format(date: Date): string`.

**Юзкейсы:**

- форматирование большого количества данных
- форматирование реактивных данных, которые могут часто меняться

**Использование:**

```ts
import { computed } from 'vue';
import { getDateFormatter } from '@/shared/lib';

const props = defineProps<{
	segments: { time: Date; value: number; }
}>();

const segmentLabelFormatter = getDateFormatter({ day: '2-digit', weekday: 'short' });

const preparedSegments = computed(() => {
	return props.segments.map(segment => ({ value: segment.value, label: segmentLabelFormatter.format(segment.time) }));
});
```

Такой подход обеспечит более производительное форматирование даты

---

## Почему не использовать Intl.DateTimeFormat напрямую

- сложно централизовать локаль
- нет единой точки конфигурации
- легко создать форматтер внутри реактивного контекста и потерять производительность
- невозможно гарантировать одинаковое поведение во всех модулях
